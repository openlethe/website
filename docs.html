Start · Quickstart

Three ways in,
pick your depth.

ASession memory with the OpenClaw plugin · simplest

The legacy Lethe service with automatic context injection. Best when you want persistent session memory for OpenClaw with zero workflow changes. (OpenClaw only — other harnesses use tracks B or C.)

# 1 · run Lethe (legacy mode, port 18483) — pulls the published image
$ docker run -d --name lethe -p 127.0.0.1:18483:18483 -v ./lethe-data:/data ghcr.io/openlethe/lethe:latest

# 2 · install the context-engine plugin from ClawHub
$ openclaw skills install lethe-memory

# 3 · set the API key (loopback needs none; anything else does)
$ ./lethe keygen                    # prints LETHE_API_KEY=lethe_…
$ export LETHE_API_KEY=lethe_…     # Lethe does NOT auto-load .env

BMemory Git + Charon — the governed stack · recommended

Versioned, reviewed, shared memory. Lethe Git owns the history; Charon owns the policy. You generate credentials for both services — nothing is hardcoded.

# 1 · Lethe Git (in the lethe repo) — generates LETHE_API_KEY + CHARON_MERGE_HMAC_KEY
$ sh scripts/prepare-local-memory-git-env.sh
$ docker compose -f docker-compose.git.yml --env-file .env.git up -d
$ curl -s -o /dev/null -w '%{http_code}\n' http://127.0.0.1:18485/api/health   # 401 = up & enforcing

# 2 · Charon (in the charon repo) — Compose pulls ghcr.io/openlethe/charon:latest
$ set -a; . ../lethe/.env.git; set +a
$ export CHARON_OAUTH_REDIRECT_URIS="https://chatgpt.com/connector/oauth/*"
$ ./setup.sh                     # .env, 3 principals, obols in secrets/, both gateways
#   — or write .env by hand: see the Environment variables section

# 3 · mint a working author credential (obols are audience-bound: mint via the Obol gateway)
$ set -a; . secrets/principal-ids.txt; set +a
$ docker compose exec charon-reviewer charon obol mint --expires 7d "$AUTHOR_ID" > secrets/author-obol.txt

# 4 · connect a local agent
$ TOKEN=$(grep -oE 'Token: obol_[A-Za-z0-9_-]+' secrets/author-obol.txt | sed 's/Token: //')
$ openclaw mcp add charon-author --url http://127.0.0.1:18486/mcp \
    --transport streamable-http --header "Authorization=Bearer ${TOKEN}"

The full ten-phase walkthrough — with expected results, restart, rotation, and backup drills — is docs/full-run.md in the Charon repo.

CChatGPT connector — remote, OAuth-only

  • Front the primary gateway (:18484) with an HTTPS tunnel; set CHARON_PUBLIC_URL to the tunnel URL and list ChatGPT in CHARON_OAUTH_REDIRECT_URIS.
  • Restart, then copy the current pairing key from the startup banner: docker compose logs charon. It regenerates on every restart — that is the only credential that does.
  • Add the connector in ChatGPT and complete the S256 PKCE flow, pasting the pairing key when asked.
  • Tokens are capped: memory.read · search · thread.read · propose. Branch/commit require CHARON_OAUTH_ALLOW_AUTHOR_SCOPES=true; review/merge/write are never granted over OAuth.
Guide · Concepts

The mental model
in eight objects.

ObjectWhat it is
changesetThe immutable unit of memory: an ordered list of semantic operations (add_memory, correct_memory, supersede_memory, mark_duplicate, add_relationship, attach_evidence, attach_verification, propose_deprecation), committed with compare-and-swap and an idempotency key. Validated at Charon, then again at Lethe before insertion.
refA named pointer to a changeset. refs/shared/* is protected accepted memory — no direct commits, ever. refs/agents/<actor>/*, refs/sessions/<actor>/*, refs/topics/* are owned by their creating principal.
idempotencyRetry the identical request with the same key → the original changeset, exactly once. Change anything under the same key → a closed failure, never a silently discarded write.
proposalA merge request from an owned ref head into a protected ref. Pinned to the exact source changeset at creation; later branch commits are not included (see stale proposals).
reviewA verdict — approve / request_changes / reject — bound to the current proposal snapshot by digest. Originators can never review or merge their own proposals.
merge envelopeThe memory-git-merge/v2 authorization: HMAC-signed, ≤15-minute TTL, single-use nonce, bound to project, ref, heads, proposal digest, reviewer, and merger. Lethe verifies it independently and consumes the nonce atomically with the CAS — replays are rejected even if the ref cycles back.
ledgerCharon's hash-chained audit log. Intent is persisted before the mutation it describes; charon ledger verify re-walks the chain. If the ledger can't write, the mutation doesn't happen.
context projectionmemory_context_at reconstructs accepted memory at an exact ref head — what a reader sees is precisely what was approved, optionally pinned in a manifest.
Guide · Roles & scopes

Who may do
what, exactly.

ProfileScopes grantedRole
readonlymemory.search · memory.read · thread.readReader — consumes accepted memory, never writes.
proposereadonly + memory.branch · memory.commit · memory.proposeAuthor — writes on owned refs, proposes crossings.
reviewreadonly + memory.review · memory.merge · proposal.reviewReviewer — independent verdicts and merges.
writepropose + review + memory.writeTrusted operator — broad authority, still fully ledgered.
  • Exact projects for mutations. A wildcard (*) grant is read-only by policy.
  • Separation is structural. A proposal originator cannot review (denied: self review) or merge (denied: self approval) its own proposal — enforced in code, not convention.
  • OAuth is capped. Browser-flow tokens get at most read · search · thread.read · propose; branch/commit only when CHARON_OAUTH_ALLOW_AUTHOR_SCOPES=true; review/merge/write never. Token scopes are re-intersected with current grants on every request.
  • Provisioning. charon principal reconcile "<name>" <profile> <project> is idempotent — re-run it any time to converge a principal's grants.

Reference · Environment variables

Every variable,
both services.

Everything below is set in .env (Charon) or .env / .env.git (Lethe) — write the file by hand; no script is required. Rules that apply everywhere: generate secrets with openssl rand -hex 32, keep values distinct per purpose, chmod 600 the file, and never commit it (.gitignore already covers .env / .env.*).

Structuring a manual .env — the short version

  • Required (Charon): LETHE_API_KEY (must match Lethe), three distinct keys CHARON_OBOL_HMAC_KEY, CHARON_OAUTH_HMAC_KEY, CHARON_MERGE_HMAC_KEY (the merge key must also match Lethe), CHARON_PUBLIC_URL, and in OAuth mode CHARON_OAUTH_CLIENT_ID, CHARON_OAUTH_REDIRECT_URIS, CHARON_OAUTH_DEFAULT_USER.
  • Required (Lethe git mode): LETHE_API_KEY and CHARON_MERGE_HMAC_KEY — the identical pair Charon has.
  • Required (Lethe legacy): nothing on loopback; LETHE_API_KEY is mandatory for any non-loopback bind.
  • Everything else has safe defaults — tune only what you need from the tables below.
  • Compose refuses to start when a :?-marked required variable is missing, and both servers validate config at boot and fail closed with a named error.

OpenClaw — plugin (session memory)

$ openclaw skills install lethe-memory

Published on ClawHub as the lethe plugin. Registers as a context engine: bootstrap, assemble, and compact hooks wire session memory automatically. OpenClaw-only — every other harness below needs no plugin.

OpenClaw — MCP client (Memory Git)

$ TOKEN=$(grep -oE 'Token: obol_[A-Za-z0-9_-]+' secrets/author-obol.txt | sed 's/Token: //')
$ openclaw mcp add charon-author --url http://127.0.0.1:18486/mcp \
    --transport streamable-http --header "Authorization=Bearer ${TOKEN}"
$ openclaw mcp reload && openclaw mcp probe charon-author

Repeat with secrets/reviewer-obol.txt for a reviewer client. Keep the two in separate agents — review independence is the point.

ChatGPT connector

  • HTTPS tunnel to :18484; CHARON_PUBLIC_URL = tunnel URL; redirect URIs include https://chatgpt.com/connector/oauth/*.
  • Pairing key from the startup banner (docker compose logs charon) — new on every restart.
  • Scopes are capped to read/propose by default; reconnect after restarts or rotation.

Claude / generic MCP client

Any client that speaks streamable-http MCP can connect to the Obol gateway. Configuration shape varies by client; the essentials:

{
  "mcpServers": {
    "charon": {
      "url": "http://127.0.0.1:18486/mcp",
      "transport": "streamable-http",
      "headers": { "Authorization": "Bearer obol_…" }
    }
  }
}
Never bypass the gateway. Agents must not connect to Lethe Git (:18485) directly — Charon is where grants, scopes, provenance, review rules, and audit logging live. Keep :18485 and :18486 on loopback.

Ops · Security model

Fail closed,
everywhere.

  • Boundary. Agents never reach Lethe directly. Charon enforces project grants, scopes, ownership, review separation, and audit on every call.
  • Credentials. Three distinct HMAC purposes (Obol, OAuth, merge); legacy single-key fallback deprecated with a startup warning. Secrets are operator-generated, mode-0600, never printed by scripts.
  • Transport. Plaintext HTTP to a non-loopback upstream is refused; OAuth is S256-PKCE-only; the browser pairing key rotates on every restart.
  • Merges. Expiring, single-use, proposal-digest-bound envelopes; Lethe independently verifies signature, shape, and nonce — replays rejected even if the ref cycles back.
  • Containers. Non-root (UID 1000/10001), cap_drop: ALL, read-only root filesystems, no-new-privileges, resource limits, healthchecks.
  • Audit. Hash-chained, MAC'd ledger written before mutations; optional external anchor detects wholesale replacement.
